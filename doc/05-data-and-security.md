## 2. 客户信息使用原则

1. **最小必要**：只取构造画像需要的特征（行业、规模、关注点、常见异议），不取身份信息。
2. **先脱敏后使用**：任何进入提示词、知识库、日志、演示视频的数据都必须是脱敏后的。
3. **聚合优先**：优先使用"某类客户的共性特征"，而不是某个具体客户的记录。
4. **不出公司边界**：若使用外部模型 API，传入内容不得包含可识别的客户信息；涉及敏感数据时优先考虑公司私有部署模型。
5. **授权确认**：接入前需确认数据归属部门同意，并符合公司保密制度。

## 3. 脱敏规则（草案）

| 字段类型 | 处理方式 | 示例 |
|---|---|---|
| 客户/公司名称 | 替换为虚构名称 | 某某科技 → 华东某制造企业 / "星河科技" |
| 联系人姓名 | 替换为姓氏+职务 | 张三 → 张经理 |
| 手机号、邮箱、地址 | 删除 | — |
| 合同金额、报价 | 区间化或按比例缩放 | 38.6 万 → 30~50 万 |
| 项目编号、合同号 | 删除 | — |
| 内部员工信息 | 删除或替换 | — |

## 4. 仓库与存储规范

- 真实/原始数据只放 `data/private/`（已加入 `.gitignore`），**禁止提交**。
- 仓库中只保留虚构或已脱敏的示例数据（如 `scenarios/*.yaml`）。
- 密钥只放 `.env`，不得出现在代码、文档、日志、截图中。
- 对话记录落库时只存工号，不存员工手机号等个人信息；日志中不打印完整对话内容。
